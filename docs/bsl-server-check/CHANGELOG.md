# Changelog — VANTEAM BSL Server check

## 1.0.0 — 29.09.2026

Первый выпуск самостоятельной проверки BSL-модулей 1С на BSL Language Server. Основа — обёртка
Vanteam BSL Check 1.1.0, из которой убран уровень OneScript. Синтаксис OneScript проверяется отдельным
`check_oscript.py`.

### Движок
- Форк BSL Language Server `v1.0.7-vanteam.1`: дисковый кэш разобранной справки 1С, `--target`,
  защита от цикла разбора при нехватке памяти, без отправки ошибок в Sentry апстрима.
- `setup_bsl_server.py` ставит движок на машину:
  - JAR релиза со сверкой SHA-256;
  - распакованный layout и AppCDS с проверкой отображения;
  - справка только ru;
  - кэш справки и tmp вне проекта;
  - `install.json` с отпечатком JDK.

### Проверка
- Только BSL LS. Вызовы oscript исключены, это проверено тестом с oscript в PATH.
- Совместимый вызов `check_bsl.py <модуль> --deep`. `--all` выполняет только BSL LS и печатает подсказку про `check_oscript.py`.
- Несколько модулей одной области — одна JVM с несколькими `--target`.
- Флаги по итогам замеров фазы 2:
  - `-XX:TieredStopAtLevel=1`, `-XX:ActiveProcessorCount=min(4, CPU)`, `-XX:+ExitOnOutOfMemoryError`, `--silent`;
  - куча 512m или 1g по объёму области.
- Защиты 1.1.0 сохранены:
  - код 3 «проверка не выполнена»;
  - строки WARN/ERROR движка → неполная проверка;
  - ровно один отчёт и одно совпадение цели по полному пути;
  - `mdoRef` при `--source-dir`;
  - неизвестная severity → неполная проверка.

### Исправлено относительно 1.1.0
- Модуль на другом диске, чем каталог проверки: штатный 1.0.7 падал в `AnalyzeCommand` (JVM код 1 → итог 3),
  потому что относительный путь между дисками не строится. Теперь работает, есть интеграционный тест.

### Проверено
- 81 модульный и 19 интеграционных тестов на реальных Java 21 и JAR форка. Все прошли, пропусков нет.
