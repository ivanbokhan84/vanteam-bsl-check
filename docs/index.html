Two checks, two forks

One command per engine

Each engine has its own fork with the changes the checks rely on. This repository holds the wrappers and ties the two together; run both after every change to a module.

1. OneScript — tools/check_oscript.py

Engine: OneScript 2.2.0-vanteam.2, oscript -checkall. One engine start for all files and every error of a module: syntax, wrong argument count, a procedure used as a function, a duplicate method with its line. Unknown 1C names are listed, not errors. Code under #Если Сервер is checked through a copy without directive lines.

76 modules of a 1C configuration: 2.4 s in one run against 50–80 s with oscript -check per file; 116 of 116 real modules checked to the end.

Fork ivanbokhan84/OneScriptMeasurements

2. BSL Language Server — tools/check_bsl.py --deep

Engine: BSL Language Server 0.29.0 (1.0.7 in the 1.1.0 release candidate), --analyze: cognitive complexity, deprecated methods, unused variables, cross-module calls. Exit code 3 when the analysis did not happen.

The Vanteam fork of BSL Language Server 1.0.7 (persistent platform-context cache, own diagnostics) is at an early stage with no releases yet, so the wrapper uses the upstream JAR.

Fork ivanbokhan84/bsl-language-server
python tools/check_oscript.py path/to/Module.bsl          # 1. OneScript
python tools/check_bsl.py path/to/Module.bsl --deep       # 2. BSL Language Server
How it decides

Exit code 3 is a first-class result

Both engines can fail quietly: a missing report, a module that is not in the report, a crashed rule, an engine that skipped metadata and still exited with 0. The wrapper checks that the analysis really happened before it looks at findings.

Tests

Mocks for the failure paths, real engines for the rest

Integration tests run real Java, BSL Language Server, OneScript and Git on fixtures: syntax errors, a minimal Designer configuration with two modules, broken or unregistered metadata, an invalid rule parameter and a locked source file. A skipped integration test is not counted as a pass.

Measurements

A JVM tuned for short runs

-XX:TieredStopAtLevel=1 and -XX:ActiveProcessorCount=min(4, CPUs), measured on BSL Language Server 1.0.7: six scenarios, a warm-up and five alternating paired rounds, a new JVM per run, 4 cores / 8 threads. Diagnostics were identical to the default JVM in every scenario.

Use it

Install and run

git clone https://github.com/ivanbokhan84/vanteam-bsl-check.git
cd vanteam-bsl-check
python scripts/fetch_dependencies.py          # BSL LS JAR, SHA-256 verified
python tools/check_oscript.py path/to/Module.bsl          # needs OneScript 2.2.0-vanteam.2 from the fork
python tools/check_bsl.py path/to/Module.bsl --deep
python tools/bsl_new_findings.py path/to/Module.bsl
